# Introibo v1.2.3 — Development Plan

**Theme:** finish the liturgical-orientation release. v1.2.3 carries forward
everything from the original v1.2 plan that has not yet shipped. Three of the
four v1.2 pillars are already built and live (see the ledger below); what
remains is the widget system in its entirety plus the calendar's year-level
orientation surfaces and a handful of verification items.

---

## Ledger: what the v1.2 plan called for vs. what already shipped

Audited against the codebase at content version 1.2.2.

### Built and shipped — NOT in 1.2.3 scope

1. **Search across all content** — full UI on both platforms
   (`Screens/Search/SearchView.swift`, `ui/search/SearchScreen.kt`); six
   content types (Prayers, Missal, Office, Reference, Saints, Calendar) with
   per-type filters; diacritic-insensitive matching both ways, pinned by
   shared golden tests (`SearchNormalizerGolden`, `SearchMatcherGolden`);
   fully offline; results route through the deep-link system.
2. **Contextual-link infrastructure** — `LinkGraph` / `LinkMarkup` /
   `LinkScanners` / `LinkTarget` / `RelatedLink` on both platforms, driven by
   declarative content data (`link_golden.json` pins the graph); targets
   resolve to a position within content (`type:id#position` grammar). The
   v1.2.5 dependency is satisfied.
3. **Liturgical calendar + Today-header entry point** — month grid, rite-aware
   (1962 / 1955 / pre-1955) with per-rite year-range bounding; jump-to-today;
   Sunday-obligation badge (✠) in cells; day-detail sheet with season, color,
   special-day flags (Ember, First Friday/Saturday, obligation), the penance
   obligations for the user's selected discipline, and a link to that day's
   Mass proper. The Today header opens the calendar.

### Not built — this IS the 1.2.3 scope

1. **Home/Lock Screen widgets** — no widget code exists on either platform.
   The entire section 2 of the v1.2 plan transfers verbatim.
2. **Calendar year overview** — the "shape of the whole year" view with
   season bands and a "you are here" marker.
3. **Upcoming-feasts preview** — next 7–14 days, on the Today screen and in
   the calendar.
4. **Quick navigation to the major moveable feasts** — Easter, Ascension,
   Pentecost, Trinity, Corpus Christi, Christ the King.
5. **Month-cell markers beyond ✠** — octave day, vigil, Ember Day, and
   penance-level pips in the grid cells themselves (the detail sheet already
   shows all of this; the grid does not).
6. **Search position-landing verification** — the `#position` grammar exists;
   verify every result type actually lands at the match position, not the
   content's top, and close any gaps.

## 1. Widgets (the release's main feature)

Everything in the original v1.2 plan section 2 applies unchanged. Summary of
the binding constraints; consult the v1.2 plan for full detail:

- **Two modes, extensible set:** Office-by-time-of-day and
  chosen-prayer-by-slot (morning/midday/evening). Mode system, config
  storage, and render switch structured so the future "Follow my Life Rule"
  mode (post-Rule-rework) is additive, not a refactor.
- **Shared-logic gate (FIRST widget task):** `OfficeSchedule.currentHourSlug`
  currently lives in the main app target. An iOS widget extension cannot call
  main-app code — extract it (behavior-identical) into a shared
  framework/target both link against before any other widget work. The
  Android widget consumes the same Kotlin logic directly. Widget and app must
  never disagree about the current hour.
- **Slot boundaries:** ship good fixed defaults aligned with the existing
  Office-time logic's notion of morning/midday/evening; optional adjustment
  in config, never required.
- **Tap-through:** opens directly into the hour/prayer, ready to pray — from
  cold launch, warm resume, and app-already-open, resolving against the
  moment of tap. Route through the existing `DeepLinkRouter` / MainActivity
  action-intent plumbing (the 1.2.2 app shortcuts already exercise the
  Android path).
- **CUT LINE (non-negotiable):** the widget surfaces, never tracks. No
  completion state, counts, streaks, progress, history, or missed-day
  framing — now or via any later addition. Refuse, don't build.
- **Config:** one small dedicated screen (mode selector; slot assignments via
  the existing prayer picker; optional boundary times). Persists across
  restart and upgrade-over-install.
- **Refresh discipline:** compute from config + clock + shared logic via OS
  timelines (WidgetKit timeline entries / AppWidget alarms at slot
  boundaries). Never poll; never assume the app is running.
- **Rendering:** Cistercian visual system; verify every size family, both
  platforms, light/dark, accessibility text sizes, no truncation.

## 2. Calendar year overview

A single scrollable view of the whole liturgical year: seasons as restrained
colored bands, major feasts marked, the user's position clearly indicated.
Rite-aware — the bands and feasts come from the active rite's ordo, and the
pre-Lent/Passiontide/octave structure must match the rite setting. Reached
from the calendar surface (and this becomes the natural landing for the
Today-header treatment if a "view the year" affordance is added there).
Reuse `ordoYearRange` and the existing per-rite ordo data; no new engine
logic — the calendar surfaces what the engine already computes.

## 3. Upcoming feasts + moveable-feast navigation

- **Upcoming preview:** the next 7–14 days' notable days (rank above feria,
  vigils, Ember days, obligations), shown near the Today header and inside
  the calendar. Pure read of the existing ordo; rite-aware.
- **Moveable-feast jump:** quick navigation to Easter, Ascension, Pentecost,
  Trinity, Corpus Christi, Christ the King for any year in the rite's data
  range. These are lookups against the ordo, not new computation.

## 4. Month-cell markers

Add octave-day, vigil, Ember, and penance-level indicators to the month grid
cells, using small pips/edge accents consistent with the existing ✠ badge.
Legibility first: the cell fill stays tinted/desaturated, saturated color only
as accent. All flags already exist in `LiturgicalContext` / the ordo rows —
this is presentation only.

## 5. Verification carried from the v1.2 plan

- Search results land at the precise match position for every content type.
- Widget QA hooks: shared-hour agreement, tap-through from all three launch
  states on both platforms, config persistence across upgrade, CUT-LINE
  check, slot-boundary correctness (test just-before/just-after each
  boundary), all sizes/accessibility, timezone change and local-midnight
  rollover (Android especially).
- Cross-cutting: rite setting, language mode, diacritics on physical Android
  hardware, date/timezone integrity — across all new surfaces.
- Calendar/engine consistency: any divergence between what the calendar (or
  widget) shows for a day and what the Mass/Office serve for that day under
  the same rite is a critical bug.

## Build order

1. Shared Office-time logic extraction (the iOS gate; smallest, unblocks the
   most).
2. Widgets: iOS WidgetKit + Android AppWidget, config screen, deep links.
3. Calendar year overview (reuses ordo data and calendar visual patterns).
4. Upcoming feasts + moveable-feast navigation + month-cell markers (small,
   independent; can land in any order after the calendar work).
5. Verification pass per section 5; ship only after it clears.
